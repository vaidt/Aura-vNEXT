# app — runnable applications

**Status: M0 IMPLEMENTATION ADMITTED (ADR-0006).**

## Purpose

Applications that are run, as distinct from `core/` (canonical semantics, which
applications call) and `cli/` (the operator surface across the whole product, still
reserved).

## What is here

The two ends of the M0 product loop, and the command line over them:

```
application event -> app/producer -> Evidence Package -> app/verifier -> VERIFIED
                                                                         TAMPERED
                                                                         INVALID
```

- [`producer/`](producer/) — builds an Evidence Package from an application decision.
  An **adapter**, not a second evidence specification: every protected value it writes
  is computed by `core/` (`core.models`, `core.canonical`, `core.chain`, `core.policy`).
  It owns the package's serialised layout and nothing else.

- [`verifier/`](verifier/) — the M0 Evidence Package verifier.

  ```sh
  python3 -m app.verifier <package-directory> --json
  ```

- [`aura/`](aura/) — the command line over both.

  ```sh
  python3 -m app.aura record --output ./aura-evidence-loan-001 \
      --policy policy.json --decision DENY --request-id loan-001 \
      --input-hash <sha256> --violation LOAN.DTI_EXCEEDED:BLOCK:0.95

  python3 -m app.aura record --append --output ./aura-evidence-loan-001 ...

  python3 -m app.aura verify ./aura-evidence-loan-001
  ```

Exit status is the machine-readable result: `0` VERIFIED, `2` TAMPERED, `3` INVALID;
`64` a command line that could not be understood, `65` an event that cannot be recorded.

## Gate

The verifier may depend on the package it is given and on `core/`. It must not depend on
the producer runtime, the original database, a network, hidden state, policy-engine
execution, or a developer environment (ADR-0006 §2). `tools/independence_check.py`
enforces this by running it in a directory containing only `core/` and `app/verifier/`
— `app/producer/` and `app/aura/` are **excluded**, because an environment holding the
producer could not show that verification does not need it.

The producer may depend on `core/`. It must not become a second place where
canonicalisation, hashing, or chain linkage is decided: `tests/product/test_producer.py`
recomputes every digest the producer wrote through `core.chain` and asserts they match,
and the committed reference package in `evidence/examples/` is generated by this
producer rather than by a fixture-only construction.

Anything placed here that derives from the frozen `Aura-IDToken` corpus requires a
transfer register entry at `TRANSFER_APPROVED` or later. Nothing here does: M0 is new
implementation, written against ADR-0005 and ADR-0006.
